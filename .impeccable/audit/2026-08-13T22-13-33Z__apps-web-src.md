# Technical audit: `apps/web/src`

**Date**: 2026-08-13 (UTC) · **Target**: the operator dashboard, all 29 files under `apps/web/src`
**Score**: **17/20** — Good (address weak dimensions)

**Method**: full source review, plus exact WCAG contrast computed from the OKLCH tokens in
`apps/web/src/styles.css` (26 pairs × both themes) and a production `vite build`. No page was
rendered in a browser: a `chrome-devtools` MCP server is available in this environment, but the
dashboard needs the API and Postgres up to show anything real, and contrast is more reliably
computed from the tokens than sampled from a screenshot.

**Binding context**: `PRODUCT.md` (register: product) and `DESIGN.md` ("The Faceplate").
`.impeccable/design.json` is a stale snapshot of the previous system and was not used.

## Anti-patterns verdict: PASS

Checked for all of them and found none. No gradient (`linear-gradient`: 0 hits), no
`background-clip: text`, no `backdrop-filter`, no side-stripe borders, no drop shadows outside the
sanctioned `0 1px 0` zero-blur edge, no pills, no hero-metric tiles, no identical card grids, no
modals, no second icon family, no `#fff`/`#000` literals, no em dashes in UI copy. Uppercase appears
only in the Engraved role.

The product slop test asks whether a Linear/Stripe-fluent user would trust this surface. They would.
The lamp component is the strongest thing here: four independent carriers of one fact (glyph shape,
lit/hollow form, text legend, color), so the design survives a greyscale print. The one genuine
strangeness is the row that opens an edit form with no disclosure affordance (P2 below).

## Executive summary

12 issues: **0 P0, 3 P1, 5 P2, 4 P3**.

Top five:

1. `--score-strong` at **1.88:1** (light) / **1.84:1** (dark) is the resting border of every control,
   field, and switch. WCAG 1.4.11 needs 3:1.
2. Inline replace destroys keyboard focus in four places (edit Endpoint, revoke token, delete
   Channel, and every Cancel that reverses them).
3. The New Channel form uses placeholder-as-label, which `DESIGN.md` §5 explicitly forbids.
4. The disable-Channel warning is styled Lamp Cut while the identical category of message twelve
   lines below is an `.advisory` — the Quarantine Rule broken against itself.
5. Endpoint rows are clickable-to-edit with no chevron, no `aria-expanded`, and no hint at rest.

**Framing on the contrast finding.** `PRODUCT.md` states that WCAG 2.2 AA was considered and _not_
adopted as a requirement, to be followed "where it costs nothing." The border fix does not cost
nothing: it visibly darkens the faceplate. The numbers below exist so the call can be made
deliberately rather than by checklist.

## Detailed findings

### P1

#### [P1] Component boundaries fail non-text contrast

- **Location**: `apps/web/src/styles.css:28` (`--score-strong`), consumed by `.control`, `input`,
  `textarea`, `.switch-plate`, `.switch-plunger`, `.lamp-hollow .lamp-glass`, `.payload`,
  `.empty-state`
- **Category**: Accessibility
- **Measured**: light `oklch(79% 0.009 195)` on `--face` = **1.88:1**, on `--well` = **1.62:1**.
  Dark `oklch(41% 0.011 195)` on `--face` = **1.84:1**, on `--well` = **2.19:1**.
- **Impact**: `DESIGN.md`'s central claim is that "every control states its affordance at rest… a
  border that only appears on hover is a defect." The border carrying that claim is nearly invisible
  to anyone with reduced contrast sensitivity; in bright office light (the stated scene) the controls
  read as flat text. The neutral hollow lamp's bezel is the _form_ channel of the four-way status
  encoding, and it sits at the same ratio.
- **Standard**: WCAG 2.2 §1.4.11 Non-text Contrast (AA) — 3:1 for UI component boundaries and
  meaningful graphics.
- **Recommendation**: `--score-strong` needs ≈`oklch(62% 0.011 195)` light and
  ≈`oklch(54% 0.011 195)` dark to clear 3:1 against _both_ Face and Well. That is a large step from
  79%/41% and will read as a harder-edged plate. Middle path: keep `--score-strong` for grooves and
  dividers, and add a `--score-control` at those values used only on `.control`, `input`, `textarea`,
  `.switch-plate`, and lamp bezels — the surfaces the criterion actually covers. `--score` (1.30:1)
  is a pure divider and is exempt.
- **Suggested command**: `/impeccable polish`

#### [P1] Focus is destroyed on every inline replace

- **Location**: `apps/web/src/pages/channel-detail/EndpointsTab.tsx:164`,
  `ChannelTokensPanel.tsx:145`, `ChannelDangerZonePanel.tsx:90`, and every Cancel that reverses them
- **Category**: Accessibility
- **Impact**: Each site unmounts the button that was just activated and mounts different content in
  its place. Focus falls to `<body>`, so the next Tab starts over at the top of the document. A
  keyboard operator who presses Revoke has to tab back through the entire page to reach Confirm — on
  the one flow where the wrong button is destructive.
- **Standard**: WCAG 2.2 §2.4.3 Focus Order (A)
- **Recommendation**: On mount of the replacement region, move focus to its first control
  (`autoFocus`, or a ref plus `focus()` in an effect); on Cancel, return focus to the trigger. The
  inline-expansion doctrine is right — this is the behavior contract it still owes. `DESIGN.md` §4
  already writes exactly this contract for overlays the system does not have; it has not been applied
  to the inline replacement it uses everywhere.
- **Suggested command**: `/impeccable harden`

#### [P1] Placeholder-as-label on the New Channel form

- **Location**: `apps/web/src/pages/ChannelDirectoryPage.tsx:77-94`
- **Category**: Accessibility
- **Impact**: Both inputs carry `aria-label` and a placeholder but no visible `<label>`. The
  placeholder disappears the moment typing starts, taking the slug's format rule with it — that rule
  is stated _only_ there and in a `title` tooltip, which is invisible to keyboard and touch.
  Placeholder text also inherits `--ink-muted`, so an empty field reads as pre-filled at a glance.
- **Standard**: WCAG 2.2 §3.3.2 Labels or Instructions (A)
- **Recommendation**: Use `.field` plus an engraved `<label>`, as every other form in the app does,
  and move the format rule to persistent helper text. `DESIGN.md` §5 Fields: "Label: the Engraved
  role, above the field, always present. No placeholder-as-label."
- **Suggested command**: `/impeccable clarify`

### P2

#### [P2] Lamp Cut on a consequence advisory

- **Location**: `apps/web/src/pages/channel-detail/ChannelSettingsForm.tsx:117-121`
- **Category**: Anti-pattern / Theming
- **Impact**: "Disabling this Channel stops fan-out to N enabled Endpoints" renders as `.error-text`
  (Lamp Cut) with `role="alert"`. Nothing has failed and nothing is invalid: the operator is being
  told a consequence. Twelve lines below, the unauthenticated-ingest warning is an `.advisory`, with
  a comment explaining precisely why an advisory may not borrow a lamp color. Two identical message
  categories, two treatments. It also makes red mean two different things on one form, which is the
  confusion `PRODUCT.md` principle 4 exists to prevent.
- **Recommendation**: `.advisory` with the `Info` glyph, and drop `role="alert"` — it re-announces as
  the switch toggles.
- **Suggested command**: `/impeccable polish`

#### [P2] Endpoint rows edit on click with no affordance

- **Location**: `apps/web/src/pages/channel-detail/EndpointsTab.tsx:161-190`
- **Category**: Anti-pattern / Accessibility
- **Impact**: The row is a `<button>` that swaps itself for an edit form, but carries no chevron, no
  `aria-expanded`, and no visible cue. Every other clickable row family (Activity, Delivery) ends in
  a disclosure chevron precisely so "does this open?" is a shape at rest. Here it is discovered by
  clicking, and what is discovered is an editable form — a heavier surprise than a detail panel.
- **Recommendation**: Add a trailing edit glyph from the existing `lucide-react` family, or, more
  consistent with the system, make edit an explicit trailing control on the row (matching the Revoke
  pattern on token rows) rather than a whole-row click.
- **Suggested command**: `/impeccable shape`

#### [P2] Forced-dark flashes light on first paint

- **Location**: `apps/web/src/components/ThemeToggle.tsx:49-56`, `apps/web/index.html`
- **Category**: Theming
- **Impact**: `applyTheme` runs in a `useEffect`, so `data-theme` is stamped only after React mounts.
  An operator who chose dark while their OS is light gets a full-brightness white flash on every
  load. In the tab-between-two-dark-editors scenario `DESIGN.md` describes, that is the worst
  possible moment for it. Operators on `system` are unaffected: `prefers-color-scheme` resolves
  before paint.
- **Recommendation**: A short blocking inline script in `<head>` that reads the same `localStorage`
  key and stamps `data-theme` before first paint. The effect stays the source of truth after mount.
- **Suggested command**: `/impeccable optimize`

#### [P2] Login form abandons the field rhythm

- **Location**: `apps/web/src/pages/LoginPage.tsx:39-58`
- **Category**: Anti-pattern (consistency)
- **Impact**: Label and input are flat siblings in a 12px gap stack, so the label sits equidistant
  from the field it names and the prose above it. `DESIGN.md` calls this out by name as the defect
  `.field` / `.field-stack` were built to fix. This is the first screen anyone sees.
- **Recommendation**: Wrap in `.field`. Add `autocomplete="current-password"` and a `name` while
  there.
- **Suggested command**: `/impeccable polish`

#### [P2] Touch targets are 36px

- **Location**: `apps/web/src/styles.css:93` (`--control-height`); `.tab` at `styles.css:793` is
  ~31px tall with 2px of horizontal padding
- **Category**: Responsive
- **Impact**: Below the 44×44 guideline. The 720px breakpoint does real compositional work — rows
  restructure, strings stop truncating — which signals that mobile is genuinely supported, but the
  controls did not get the same treatment. Tabs are the worst case: 2px of side padding means the tap
  target is exactly the glyph-plus-caps label.
- **Standard**: WCAG 2.2 §2.5.8 Target Size Minimum (AA, 24×24) is met; §2.5.5 Enhanced (AAA, 44×44)
  is not.
- **Recommendation**: Under 720px raise `--control-height` to 44px and pad tabs to match. Desktop
  keeps its density.
- **Suggested command**: `/impeccable adapt`

### P3

#### [P3] The lip tokens are untinted white and black

- **Location**: `apps/web/src/styles.css:36-38`, `:132-134`
- **Category**: Theming
- `--lip-light: oklch(100% 0 0 / 0.9)` and `--lip-shade: oklch(0% 0 0 / 0.35)` are literal white and
  black at chroma 0. The file's own header comment claims "no untinted grey, no `#fff`, and no
  `#000` in this file," and The Anodized Grey Rule requires hue 195 at chroma 0.002–0.011. Composited
  at 90% over Face the difference is nearly invisible, but the rule is stated as absolute and this is
  the one place the code contradicts it. Either tint them or amend the rule to exempt light overlays.
- **Suggested command**: `/impeccable polish`

#### [P3] The dark palette is duplicated verbatim

- **Location**: `apps/web/src/styles.css:120-172`
- **Category**: Theming
- 21 tokens are declared identically in the media query and in the `[data-theme="dark"]` block. The
  three-state theme genuinely requires both selectors, but nothing keeps them in sync: the next token
  added to one will silently miss the other, breaking exactly one of the two dark paths. Hoist the
  values into a shared declaration with a grouped selector, or generate them.
- **Suggested command**: `/impeccable extract`

#### [P3] `.payload` nests a scroll region

- **Location**: `apps/web/src/styles.css:1086-1087`
- **Category**: Responsive / doctrine drift
- `max-height: 220px; overflow-y: auto` inside the page, against `DESIGN.md` §6: "Don't nest an
  `overflow-y: auto` region inside the page. The document scrolls." Capping a payload is defensible
  — an unbounded body would swamp the Activity list — but the doctrine currently says otherwise.
  Amend the rule with the payload exemption, or switch to a collapsed-with-expand treatment.
- **Suggested command**: `/impeccable polish`

#### [P3] One 426 kB chunk, no route splitting

- **Location**: build output, `dist/assets/index-*.js` — 426.42 kB, 130.08 kB gzip
- **Category**: Performance
- React 19, react-router, and TanStack Query are most of it; `lucide-react` tree-shakes cleanly
  (verified: no `createLucideIcon` factory retained in the bundle). For an internal,
  always-warm-cache tool this is acceptable, which is why it is P3 — but there is no `React.lazy` on
  the two routes and no `theme-color` meta. Worth revisiting only if cold-cache first load becomes a
  complaint.
- **Suggested command**: `/impeccable optimize`

## Patterns and systemic issues

1. **Focus is not part of the inline-expansion contract.** `DESIGN.md` wrote a precise focus contract
   for overlays the system does not have, and none for the inline replacement it uses everywhere.
   Four sites, one root cause.
2. **`--score-strong` is doing two jobs.** It is simultaneously a decorative groove and a functional
   component boundary. Those carry different contrast obligations, and one token cannot satisfy both
   without over-darkening the grooves.
3. **The consequence-advisory pattern is inconsistently applied.** Three sites use `.advisory`
   correctly, with reasoned comments; one uses Lamp Cut. The pattern is right, the coverage is not.
4. **Forms drift from the field system at the edges.** Login and New Channel — the two entry points
   — are the two forms that do not use `.field`. Both likely predate it.

## Positive findings

- **The lamp is genuinely excellent.** Four independent encodings of one fact, with `pending` versus
  `in_progress` separated by form _and_ glyph _and_ label. This satisfies `PRODUCT.md`'s hard
  constraint properly rather than nominally.
- **Every text pair passes AA; most pass AAA.** Ink on Face is 16.47:1 light and 13.19:1 dark. Both
  lamp colors clear 4.5:1 on all three grounds in both themes. The accent clears it on its own wash
  (4.83:1 light, 5.06:1 dark) — the hardest pair in the system, and it holds.
- **The token system is exemplary for this register.** Every value defined for both themes,
  `color-scheme` set, a three-state theme with the media query correctly guarded against forced
  light, and zero hard-coded colors across 3,900 lines of TSX.
- **Performance decisions are reasoned, not defaulted.** Polling pauses on `visibilitychange` and
  resumes with an immediate fetch; the skeleton's 225ms delay is CSS, avoiding a timer, a second
  render, and cleanup; animation is confined to `opacity` and `transform`; `prefers-reduced-motion`
  is honored in both places motion exists.
- **Copy is in the domain's voice throughout.** Empty states teach the next action
  (`POST /ingest/<slug>`), errors name the constraint, and there is no reassurance copy anywhere.
- **The comments carry the reasoning.** Nearly every non-obvious choice cites the rule it follows or
  the defect it fixed, which is why this audit could check spec against code rather than guess at
  intent.

1. **[P1] `/impeccable harden`** — restore focus on all four inline-replace sites: move focus into
   the confirm region, return it to the trigger on cancel.
2. **[P1] `/impeccable clarify`** — real labels on the New Channel form, format rule as persistent
   helper text.
3. **[P1] `/impeccable polish`** — decide the `--score-strong` question: split off a
   `--score-control` at 62%/54%, or record in `DESIGN.md` that 1.88:1 is a deliberate, accepted
   trade.
4. **[P2] `/impeccable shape`** — the Endpoint row's edit affordance.
5. **[P2] `/impeccable optimize`** — inline theme-boot script to remove the light flash.
6. **[P2] `/impeccable adapt`** — 44px controls and tabs below 720px.
7. **[P3] `/impeccable extract`** — deduplicate the dark palette into one shared declaration.
8. **[P3] `/impeccable polish`** — tint the lip tokens, fix the Lamp Cut advisory, `.field` the login
