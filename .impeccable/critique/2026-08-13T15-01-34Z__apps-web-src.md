#### Anti-Patterns Verdict

**LLM assessment.** This does not read as AI-generated in the usual sense: there are no gradients, no glassmorphism, no hero-metric tiles, no illustration-heavy empty states. The failure is the opposite one. It reads as **un-designed**: a competent developer's default scaffold, Tailwind indigo on grey, every region wrapped in an identical rounded card, one width for everything. The register reference calls the product bar "earned familiarity", and this clears the familiarity part but not the earned part. Nothing here is wrong enough to distrust; nothing is considered enough to feel built on purpose.

Two shared-law violations are real. `.card` is applied to five structurally different things (a create form, a list, a settings form, a token panel, an editing row), which is the "wrap everything in a container" failure, and `EndpointsTab` renders `<li className="card">` inside `<section className="card">`, which is a **nested card**: always wrong. The side-stripe is the only hard ban.

**Deterministic scan.** 13 findings across 10 files, 1 ban and 12 warnings.

- **`side-stripe-border` (ban), styles.css:393.** `border-left: 2px solid var(--primary)` on `.delivery-detail`. Confirmed, matches the DESIGN.md Don't.
- **`pure-black-white` (warn), styles.css:3.** `--surface: #ffffff`. Confirmed.
- **`em-dash` (warn), 10 hits** across three page files. Eight are genuine prose copy. Two are false positives in spirit: `DeliveryDetail.tsx:72` and `:100` use `"—"` as a null-value glyph for a missing HTTP status code, which is standard tabular convention rather than copy. They still deserve a change, because a screen reader announces the character and "no status code" is more useful than a dash.
- **`generic-sans-font` (warn), styles.css:11.** **False positive for this project.** The product register explicitly sanctions system font stacks, and DESIGN.md commits to one on purpose. Dismiss it; it should go in the ignore list.

The detector caught the `#ffffff` and the stripe that Assessment A had already flagged, and it caught the em-dash spread, which Assessment A had not enumerated. Assessment A caught the nested card and the structural issues the detector lists under `needsVisualReview` (nested cards, modal-as-first-thought) as unresolved without a browser.

**Visual overlays.** Not available. No browser automation tool is exposed in this session, so no live page was loaded and no script injection was attempted. There is no user-visible overlay. Fallback signal: source-level review plus CLI detector only. The four `needsVisualReview` items were judged from source, and the nested-card finding is a source-level confirmation of one of them.

#### Overall Impression

The information architecture is right and the domain modeling is genuinely excellent. Drilling Channel → Broadcast → Delivery → Attempt as nested inline expansions is the correct shape, it honors ADR 0004, and it makes PRODUCT.md's "one path from symptom to cause" real. The bones are good.

What's missing is the first principle in PRODUCT.md: **health before detail**. The landing page is supposed to answer "which Channels exist and are they healthy?" It answers the first half only. A Channel row shows a slug, a description, an enabled dot, and an endpoint count. There is no failure signal anywhere on the directory. An operator doing the routine morning sweep, which PRODUCT.md names as the single most frequent job, cannot see that a Channel is dead-lettering without opening it, opening its Activity tab, and reading fan-out summaries row by row. The product's primary use case currently requires exhaustive manual search.

That is the single biggest opportunity, and it is a bigger win than the entire visual re-skin.

#### What's Working

- **Domain vocabulary discipline.** Channel, Endpoint, Broadcast, Replay, Delivery, Attempt are used precisely and capitalized consistently, in labels, empty states, and error messages. The Replay comment at `ChannelDetailPage.tsx:264` even preserves the Replay-versus-Retry distinction from ADR 0003. This is rarer than it sounds and it is why heuristic 2 scores 4.
- **Inline progressive disclosure instead of modals.** Broadcast detail, Delivery detail, and Endpoint editing all expand in place. Nothing is a dialog. The nesting depth communicates the data model for free, and the operator never loses their scroll position in Activity.
- **Error handling that preserves work.** `InlineLoadError` gives a retry next to the failure, forms keep their values when a submit fails, `role="alert"` is applied consistently, and the headers validation message names the fix with an example rather than saying "invalid".

#### Priority Issues

**[P0] The Channel directory hides failure**

- **Why it matters:** PRODUCT.md's first principle is "health before detail" and the top-frequency job is "confirm at a glance that Channels are healthy and nothing is dead-lettering". The directory shows `endpointCount` and an enabled dot; neither reports health. During an incident the operator opens the app and learns nothing, then has to enter each Channel in turn. ADR 0004 states the landing page should answer health "in the first two seconds"; it does not answer it at all.
- **Fix:** Put a dead-letter and failure count on the Channel row, scoped to a recent window, and sort or mark unhealthy Channels first. The Endpoints tab already surfaces `successRate24h`, `p95Ms`, and `autoDisabledAt`, so the aggregates exist at the Endpoint level; the equivalent is needed at the Channel level. Show auto-disabled Endpoint count on the row too, since an auto-disabled Endpoint is silent failure by definition.
- **Suggested command:** `/impeccable craft channel-health-signal`

**[P1] Status is encoded in color alone, violating the one hard accessibility requirement**

- **Why it matters:** PRODUCT.md makes this a hard requirement, not a preference. `.status-dot` is an 8px circle differing only in fill (`--success` green versus `--muted` grey) with no text, no title, and no `aria-label`, and it is the sole enabled/disabled indicator on both Channel rows and Endpoint rows. To a deuteranopic operator, and to a screen reader, an enabled Channel and a disabled one are identical. Separately, the `pending` pill uses `#4338ca`, which is `--primary-hover`, so "pending" and "the accent color for selection" are literally the same color.
- **Fix:** Give the dot a text label or replace it with the status stamp vocabulary from DESIGN.md, which uses outlined-versus-filled form as well as color. Re-anchor the pending pill off the accent.
- **Suggested command:** `/impeccable harden apps/web/src/styles.css`

**[P1] Destructive and breaking actions have no guards**

- **Why it matters:** Three unguarded paths. Revoking an ingest token is instant, irreversible, and silently breaks whichever producer was using it. Renaming a Channel slug in Settings changes the public `POST /ingest/:slug` URL and breaks every live caller, with no warning that the slug is a production integration point. Unchecking `enabled` halts all ingest for the Channel. All three are a single click, and Revoke sits inline in a list where the adjacent rows look identical. This is heuristic 5 scoring 1.
- **Fix:** Confirm Revoke inline (the row becomes "Revoke this token? Yes / Cancel", not a modal). Show the current ingest URL next to the slug field so the consequence of a rename is visible at the point of edit. Warn on disable when the Channel has enabled Endpoints.
- **Suggested command:** `/impeccable harden apps/web/src/pages/ChannelDetailPage.tsx`

**[P1] No URL routing, so nothing is shareable or bookmarkable**

- **Why it matters:** Route state lives in `useState` in `App.tsx`. A Channel has no URL. PRODUCT.md describes a small team, and the natural act of that team is pasting a link: "this Channel is dead-lettering, look". That is impossible. Browser Back does not work either, so the browser's own affordance for "user control and freedom" is dead, which is most of why heuristic 3 and 7 score low. A refresh during debugging drops the operator back to the directory and loses their place.
- **Fix:** Real routing on `/channels/:id`, with the active tab and the expanded Broadcast in the URL. This is the highest ratio of user value to implementation effort on the list.
- **Suggested command:** `/impeccable craft url-routing`

**[P2] Uniform visual weight; the card is doing no work**

- **Why it matters:** Five structurally different regions share one `.card` treatment, and `EndpointsTab` nests a card inside a card, which is an absolute ban. Every panel has the same 20px padding, the same 12px radius, the same border, on a 720px column that wastes a desktop viewport the operator is using for dense row scanning. Nothing on any screen is ranked, so the eye has no entry point and the operator re-reads the layout on every visit. This is the "visual noise floor" violation and the main driver of the heuristic 8 score.
- **Fix:** Drop the card wrapper from regions that are just lists, vary padding by nesting depth, widen the column for tabular regions while keeping prose capped, and remove the nested card entirely.
- **Suggested command:** `/impeccable layout apps/web`

#### Persona Red Flags

**Alex (Power User)** is the operator PRODUCT.md actually describes.

- Cannot bookmark or link a Channel; every visit restarts at the directory and re-navigates by hand.
- No keyboard path: rows are `<button>` so they are tabbable, but there is no shortcut, no type-to-filter, no way to jump between Channels.
- The API gained slug and url filtering in commit `38cdac6`; `api.listChannels()` accepts no parameters, so the filter is unreachable. With 30 Channels the directory becomes a scroll-and-scan exercise.
- Activity paginates by "Load more" only, so reaching an older Broadcast means repeated clicks with no jump or date filter.
- Every panel polls independently on its own 5s timer, so expanding three Deliveries starts three more loops with no visible cost and no pause control.

**Jordan (First-Timer)**, an engineer set up with the operator key on day one.

- Lands on an empty directory. The only instruction is "No Channels yet, create one above." Nothing explains what a Channel is for or what happens after creating one.
- After creating a Channel, there is no next-step guidance and, critically, **the ingest URL is never shown**. The one place `POST /ingest/<slug>` appears is the Activity empty state, which vanishes the moment a Broadcast arrives. Jordan must read the README to learn the product's single most important string.
- Mints a token, sees it once as inline `<code>` with no copy button and no "this will not be shown again" warning before minting. Losing it means minting another.
- The "Accept unauthenticated ingest" checkbox is a genuine security decision presented as a plain checkbox; its explanation appears only after it is already checked.

**Sam (Incident Responder)**, generated from PRODUCT.md's reactive path.

- Arrives asking "did the billing webhook go out?" and the directory gives no failure signal, so triage starts with guessing which Channel to open.
- Once inside, Activity rows lead with a timestamp and a body preview; the fan-out summary is last, muted, and rendered as a sentence ("3/5 succeeded, 2 dead-lettered") rather than as a scannable column, so failing Broadcasts do not stand out in a list.
- An auto-disabled Endpoint, which is the silent-failure case, is reported as grey metadata text on the Endpoints tab, styled identically to a timeout value.

#### Minor Observations

- `ChannelDirectoryPage.tsx:103` renders "2 endpoints" in lowercase while the rest of the UI treats Endpoint as a proper noun. DESIGN.md's Domain Word Rule makes this a violation.
- `.error-with-retry` is referenced in `InlineLoadError.tsx:4` but is not defined anywhere in `styles.css`. Dead class.
- The Retry button on a dead-lettered Delivery is a full primary button, giving a recovery action inside a nested detail panel more visual weight than "Save changes" on the settings form.
- Login says "Sign in with the operator API key" above a field labeled "Operator API key", which restates the label. The line should say where to find the key instead.
- `usePolling` has no `document.hidden` check, so a backgrounded tab polls every list every 5 seconds indefinitely.
- Timestamps use `toLocaleString()` everywhere. For scanning a Broadcast list, relative time ("4m ago") is faster to compare, and the absolute value belongs in a `title`.
- No `<title>` differentiation per route, so every browser tab reads the same, which compounds the no-routing problem.
- Body copy has no max line length; the 720px column happens to approximate it, but the constraint is incidental rather than stated.

#### Questions to Consider

- If the directory could show only one number per Channel, which number would end the morning sweep in two seconds without opening anything?
- The Broadcast row leads with a timestamp. Is the timestamp what an operator scans for, or is it the fan-out result, and should the columns swap?
- What would this look like if the Channel were a URL instead of a piece of React state?
- Auto-disabled Endpoints are the only truly silent failure in the system. Should they interrupt the operator rather than wait to be found?
- The interface is honest about failure but not urgent about it. Where exactly is the line between "failure is information, not alarm" and failure being too quiet to notice?
