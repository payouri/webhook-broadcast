# Retry, dead-letter, and Endpoint auto-disable

Outbound Delivery treats any `2xx` as success; retries on network/TLS errors, timeouts, `408`, `429`, and `5xx`; other `4xx` fail the Delivery immediately (`failed`). Global env controls attempts (default 8), exponential backoff with jitter (5s base, 1h cap), and HTTP timeout (10s, overridable per Endpoint). `Retry-After` on 429/503 is honoured up to the backoff cap. Exhausted retries mark the Delivery `dead_lettered` (terminal on the Postgres row — not a separate DLQ); the operator may re-queue that Delivery, which is distinct from Broadcast replay. An Endpoint that stays in a failure streak for `ENDPOINT_AUTO_DISABLE_AFTER_MS` (default 1h) is auto-disabled; only an operator re-enables it. Per-Endpoint ordering is not promised. Operator alerting stays out of this decision and remains fog.
